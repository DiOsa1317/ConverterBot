# UnitMaster Bot

**UnitMaster** — это Telegram-бот для мгновенного перевода единиц измерения. Он поддерживает конвертацию валют и физических величин (длина, вес, температура).

## Roadmap: План развития

### Задача 1: Ядро конвертации
*   Конвертация валют (доллары, евро, юани, тенге, рубли).
*   Конвертация физических величин (км в мили, кг в фунты, градусы по Цельсию в градусы по Фаренгейту).
*   Распознавание сообщений формата «число из_чего в_что».
*   Команда /help для просмотра доступных вариантов перевода.
*   Понятные сообщения об ошибках при неверном формате ввода.

**Перевод валют**
> **User:** `100 usd to rub`  
> **Bot:** `100 USD = 9 250.50 RUB`

**Физические величины**
> **User:** `5 km to miles`  
> **Bot:** `5 km = 3.10686 miles`

**Обработка ошибок**
> **User:** `привет`  
> **Bot:** `Я пока умею переводить единицы. Попробуйте формат: [число] [откуда] в [куда]. Например: 10 kg to lbs`

### Задача 2: Актуальные курсы валют
*   Использование актуальных курсов валют (обновление данных каждые 6 часов).
*   При запросе справки о валютах выводится информация о дате и времени последнего обновления данных.
*   Удобные инлайн-кнопки для выбора типа перевода и конкретных единиц измерения.

### Задача 3: История переводов и кастомные единицы
*   **История конвертаций:** Возможность просмотреть последние 5 успешно выполненных переводов.
*   **Кастомные единицы:** Возможность добавить собственную единицу измерения с заданным коэффициентом конвертации относительно стандартной единицы (например, "1 my_token = 50 RUB").

#### 3.1. История переводов (с пагинацией)
*   Доступна через кнопку `История` в главном меню или команду `/history`.
*   На одной странице отображается **5 записей**, сортировка — от новых к старым.
*   Навигация осуществляется через инлайн-кнопки `Назад` и `Вперёд` под списком.
*   Текущая страница отображается текстом в заголовке сообщения.

> User: `нажимает на кнопку [ История ]`  
> Bot:  
> **Ваша история переводов (страница 1 из 3):**
>
> 1. `100 USD` → `9 250.50 RUB` *(07.11.2026, 14:30)*
> 2. `5 km` → `3.10686 miles` *(07.11.2026, 14:28)*
> 3. `1 kg` → `2.20462 lbs` *(07.11.2026, 12:15)*
> 4. `2500 RUB` → `27.03 USD` *(06.11.2026, 19:45)*
> 5. `10 my_token` → `500.00 RUB` *(06.11.2026, 18:02)*
>
> [ Вперёд ]  
> [ Очистить историю ] [ В главное меню ]

**Сценарий перехода на следующую страницу:**
> User: `нажимает на кнопку [ Вперёд ]`  
> Bot: *(редактирует то же сообщение)*  
> **Ваша история переводов (страница 2 из 3):**
>
> 6. `20 °C` → `68.00 °F` *(05.11.2026, 10:12)*
> 7. `3 miles` → `4.82803 km` *(05.11.2026, 09:50)*
> 8. `50 EUR` → `5 025.00 RUB` *(04.11.2026, 22:10)*
> 9. `150 cm` → `4.92126 ft` *(04.11.2026, 20:30)*
> 10. `75 CNY` → `975.00 RUB` *(03.11.2026, 15:00)*
>
> [ Назад ] [ Вперёд ]  
> [ Очистить историю ] [ В главное меню ]

**Сценарий на последней странице:**
> User: `нажимает на кнопку [ Вперёд ]` *(на странице 3 из 3)*  
> Bot:  
> **Ваша история переводов (страница 3 из 3):**
>
> 11. `1000 g` → `1.00 kg` *(02.11.2026, 11:20)*

> *(кнопка "Вперёд" скрыта, так как это последняя страница)*

#### 3.2. Добавление кастомных единиц измерения
*   Позволяет создать собственную пару единиц и задать курс конвертации между ними.
*   Добавленные единицы сразу становятся доступны для использования в обычных переводах.

> **User:** *нажимает на кнопку* [ Мои конверсии ]  
> **Bot:**  
> **Прямые конверсии кастомных единиц**  
> [ Добавить конверсию ] [ Мои конверсии ]  
> [ Обновить конверсию ] [ Удалить конверсию ]  
> [ В главное меню ]

**Сценарий добавления новой конверсии:**
> **User:** *нажимает на кнопку* [ Добавить конверсию ]  
> **Bot:** Шаг 1. Назовите исходную единицу (только латиница и _):  
> **User:** `chocolate`  
> **Bot:** Отлично. Теперь укажите целевую единицу (например, calorie).  
> **User:** `calorie`  
> **Bot:** Укажите курс: сколько calorie содержится в 1 chocolate?  
> **User:** `50`  
> **Bot:** Готово! 1 chocolate = 50 calorie  
> Используйте кнопки меню для выбора типа перевода.  
> [ Валюты ] [ Температура ]  
> [ Вес ] [ Длина ]  
> [ Мои конверсии ] [ История ]

**Использование кастомной единицы:**
> **User:** `10 chocolate to calorie`  
> **Bot:** `10.0000 chocolate = 500.0000 calorie` *(по вашему кастомному курсу)*

**Обработка ошибок (Кастомные конверсии):**
> **User:** `my token` *(на шаге 1, содержит пробел)*  
> **Bot:** Название должно содержать только латинские буквы и _. Попробуйте ещё раз.

> **User:** `пятьдесят` *(на шаге 3, вместо числа)*  
> **Bot:** Ошибка формата. Введите число, например, 250 или 50.5.

> **User:** `-5` *(на шаге 3, отрицательное число)*  
> **Bot:** Курс должен быть больше 0.

### Задача 4: База данных и рефакторинг
#### 4.1. База данных
Перенести стандартные единицы измерения и параметры конвертации из
Java-кода в H2, чтобы конвертеры получали коэффициенты из базы данных.
Сохранить существующие механизмы истории переводов и пользовательских
единиц.

Предлагается использовать две новые таблицы: для стандартных единиц и
их конвертаций. Существующие таблицы `custom_conversions` и
`conversion_history` оставить без изменений.

Такой вариант не требует создавать отдельную таблицу для каждой
категории и не усложняет текущую архитектуру проекта.
Предлагаемая структура БД

##### Таблицы

**Таблица `conversion_units`**  
Справочник стандартных единиц измерения.

| Поле | Тип H2 | Ограничения | Назначение |
|---|---|---|---|
| `id` | `BIGINT AUTO_INCREMENT` | `PRIMARY KEY` | Уникальный идентификатор единицы |
| `code` | `VARCHAR(32)` | `NOT NULL`, `UNIQUE` | Код единицы, например `USD`, `KM`, `KG` |
| `name` | `VARCHAR(100)` | `NOT NULL` | Название единицы |
| `category` | `VARCHAR(20)` | `NOT NULL` | Категория: `CURRENCY`, `LENGTH`, `WEIGHT`, `TEMPERATURE` |

Примеры записей:

| id | code | name | category |
|---|---|---|---|
| 1 | `USD` | Доллар США | `CURRENCY` |
| 2 | `EUR` | Евро | `CURRENCY` |
| 3 | `RUB` | Российский рубль | `CURRENCY` |
| 4 | `KM` | Километр | `LENGTH` |
| 5 | `MILE` | Миля | `LENGTH` |
| 6 | `KG` | Килограмм | `WEIGHT` |
| 7 | `LB` | Фунт | `WEIGHT` |
| 8 | `CELSIUS` | Градус Цельсия | `TEMPERATURE` |
| 9 | `FAHRENHEIT` | Градус Фаренгейта | `TEMPERATURE` |

Коды должны совпадать с кодами, которые использует приложение при
разборе пользовательского запроса.

**Таблица `conversion_rates`**  
Хранит параметры перевода между двумя стандартными единицами измерения.

| Поле | Тип H2 | Ограничения | Назначение |
|---|---|---|---|
| `from_unit_id` | `BIGINT` | `NOT NULL`, внешний ключ | ID исходной единицы |
| `to_unit_id` | `BIGINT` | `NOT NULL`, внешний ключ | ID целевой единицы |
| `multiplier` | `DECIMAL(20, 10)` | `NOT NULL` | Коэффициент умножения |
| `offset_value` | `DECIMAL(20, 10)` | `NOT NULL`, по умолчанию `0` | Дополнительное смещение |

Первичный ключ составной: (`from_unit_id`, `to_unit_id`).

Формула перевода:

```text
result = value * multiplier + offset_value
```

Для большинства физических величин `offset_value` равен `0`.

Для температуры смещение необходимо. Например, перевод из Цельсия в
Фаренгейт:

``` text
F = C * 1.8 + 32
```

Примеры записей:

| from_unit_id | to_unit_id | multiplier | offset_value |
|---:|---:|---:|---:|
| 1 | 3 | 82.0000000000 | 0 |
| 3 | 1 | 0.0121951220 | 0 |
| 4 | 5 | 0.6213710000 | 0 |
| 8 | 9 | 1.8000000000 | 32.0000000000 |

При обновлении валютных курсов они заменяются полученными значениями.

##### Что в итоге будет в существующей БД

| Таблица | Назначение | Изменения |
| --- | --- | --- | --- |
| `conversion_history` | История конвертаций пользователей | Не требуется |
| `custom_conversions` | Пользовательские коэффициенты конвертации | Не требуется |
| `conversion_units` | Справочник стандартных единиц | Новая |
| `conversion_rates` | Параметры перевода стандартных единиц | Новая |

#### 4.2. Обновление и расширение тестов

**Модульные тесты**

- Проверить существующие тесты и обновить их при необходимости.
- Проверить разбор корректных и некорректных пользовательских запросов.
- Проверить распознавание стандартных и кастомных единиц.
- Проверить работу конвертеров с коэффициентами, полученными из БД.
- Проверить перевод температуры с учётом дополнительного смещения.
- Проверить обработку ситуаций, когда необходимые данные отсутствуют.

**Интеграционные тесты приложения**

Добавить тесты, проверяющие полный сценарий взаимодействия пользователя с приложением: от получения текстового сообщения до формирования ответа бота.

Тесты должны проверять:

- Пользователь отправляет корректный запрос на конвертацию валюты — приложение возвращает правильный результат.
- Пользователь отправляет запрос на конвертацию физической величины — приложение возвращает правильный результат.
- Пользователь отправляет запрос на конвертацию температуры — приложение возвращает правильный результат.
- Пользователь отправляет запрос с кастомной единицей — приложение использует сохранённый пользовательский коэффициент.
- Пользователь отправляет запрос с неизвестной единицей или некорректным форматом — приложение возвращает сообщение об ошибке.
- Пользователь запрашивает историю конвертаций — приложение возвращает сохранённые записи.

Для интеграционных тестов используем H2 и тестовые данные. Взаимодействие с реальным Telegram API и внешними сервисами в тестах не требуется.
